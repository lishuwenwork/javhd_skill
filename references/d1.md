# Cloudflare D1 上传记录

使用 [Cloudflare 官方 REST Query API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)，不需要额外部署 Worker。请求为 `POST https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/d1/database/{DATABASE_ID}/query`，令牌放在 Bearer 请求头，SQL 和参数分开传递。凭据只从本地配置读取，不输出到日志。

## 配置与初始化

在本地 `config.json` 填写 `ACCOUNT_ID`、`DATABASE_ID`、`API_TOKEN`。Token 需要目标账户的 D1 读写权限。D1 跟随运行环境的标准 HTTP/HTTPS 代理变量，不使用 Telegram 代理或夸克 Node 预加载器。

```text
<PYTHON> -m pip install -r <SKILL_ROOT>/requirements.txt
<PYTHON> -I <SKILL_ROOT>/scripts/main.py --init-db
```

`--init-db` 只初始化表并核对所需列，不登录或上传；正常上传前也会自动检查。SQL 位于 [schemas/d1.sql](../schemas/d1.sql)，使用 `CREATE TABLE IF NOT EXISTS`，不删除或重建已有数据；同名表结构不兼容时报告失败，不擅自迁移。`--check` 只显示 `d1_config_ready` 和 `snowflake_id_version`，不联网，不证明 Token 有效。

## 表 video_uploads

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY | [snowflake-id](https://pypi.org/project/snowflake-id/) 生成的雪花 ID，以十进制字符串存储和传输，避免 API 大整数精度损失 |
| `video_id` | TEXT UNIQUE | 视频 ID，每个视频一条最新记录 |
| `title_zh` | TEXT | 网站原生中文标题 |
| `title_en` | TEXT | 当前播放接口或详情页提供的原生英文标题，缺失时为空，不自动翻译或从 slug 猜标题 |
| `detail_url` | TEXT | 实际解析的详情页 URL |
| `cover_url` | TEXT | 站点封面图 URL |
| `preview_url` | TEXT | 站点预览 URL；本地生成预览时为空，不用本地路径冒充 URL |
| `telegram_status` | INTEGER | `0` 未确认完整成功/失败，`1` 全部分段确认发布成功 |
| `quark_status` | INTEGER | `0` 未确认成功/失败，`1` 取得官方确认的文件 ID |
| `telegram_message_ids` | TEXT | 响应中的正片消息 ID，按段顺序以英文逗号连接，不含动态预览消息 ID |
| `quark_file_id` | TEXT | 官方上传或续传响应的文件 ID |

初始状态为 0。电报部分相册成功而后续失败时保留已确认正片 ID，状态仍为 0。元数据缺失时留空；完整视频的临时下载链接不写入数据库或恢复清单。

`SNOWFLAKE_INSTANCE_ID` 可选，范围 0–1023、默认 0；多个安装同时写同一数据库时分别设置不同值。同一安装受运行锁保护，生成器也有线程锁；主键冲突或时钟异常会报错，不覆盖另一视频。

## 保存与恢复

- 开始前确认 D1 可用并取得记录。新 `--id`/批量任务更新该视频最新结果，保留原雪花主键并重置本次状态；重复提交仍会上传。`--retry` 继续原记录，不重置已成功端。
- 解析后、完整视频下载前保存元数据。任一端确认成功后先保存临时恢复状态，再立即更新对应平台列，不等待另一端；两端分别写各自字段，避免并发覆盖。
- 结果的 `record_id` 是 D1 主键。`db_recorded=true` 表示本次元数据及两端结果均确认保存，不等于两端都成功。核对 HTTP 状态、外层 success、查询 success 和返回记录 ID 后才确认写入。
- D1 失败不改变已确认的上传状态，不退回文件记录。通知追加 `（D1记录未确认）`、返回非零码并保留任务。`--retry` 跳过成功端；两端都成功时只补写 D1。两端与 D1 均确认成功后才自动清理。
- 不再写 `.state/uploaded-ids.json`、`result-{id}.json` 或 `batch-result.json`。本次进程通过 `result`/`batch_result` 反馈结果，长期业务记录以 D1 为准。锁拒绝等未开始调用不能改写其他执行中的任务。
- 登录会话、二维码/登录状态、锁与失败任务 `upload-task.json` 仍在本地。清单保存 `d1_record_id`、补写元数据和已确认远端 ID，成功收尾后随媒体清理；不保存 API_TOKEN、Cookie 或完整视频临时链接。
- 用户选择删除只清理指定本地任务目录，不删 D1 行。旧 ID 历史不足以补出完整字段，不自动导入、删除或继续更新旧记录文件。

无实际凭据时只执行模拟 HTTP 与真实本地 SQLite 测试，不能声称已完成线上建表或验收。
