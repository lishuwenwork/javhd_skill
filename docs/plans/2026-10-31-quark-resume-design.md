# 夸克断点续传

用户要求夸克采用断点续传，同时沿用失败保留文件、等待用户选择重试或删除，以及双端成功才清理的规则。

1. 新任务清单明确保存夸克是否开始过上传。开始前记录原文件指纹、CLI 会话、同名同大小的已有记录 ID；收到官方任务 ID 即原子保存，和电报结果更新共用线程锁。
2. 失败后重试已有记录时只调用 `upload resume --record-id ... --file-path ...`。没有直接取得 ID 时，用开始前后的任务差集、文件名、大小和创建时间匹配唯一记录；零条或多条均停止。缺失或过期的断点、已成功但结果未确认的记录、旧任务无续传信息，均不降级为全量上传。尚未开始夸克上传的新格式任务可正常开始首次上传。
3. 恢复前核对保留文件指纹，复用会话。恢复成功必须同时满足匹配记录的成功 list 文件 ID 和最终成功 result；进度或仅有任务 ID 不算成功。
4. 超时/中止先通过项目预加载器触发官方 SIGINT 处理，给保存断点留出短暂时间，再强制终止。没有可恢复断点时如实保留文件，不保证物理断电也一定有断点。
5. 更新 README、执行说明和 ZIP 白名单，验证模拟 CLI 跨实例恢复、错误分支、双端状态并发保存、真实 Node 取消协议及现有代理回归；不做真实账号或线上上传。
