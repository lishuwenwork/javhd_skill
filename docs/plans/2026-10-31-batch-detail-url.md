# Batch and detail URL Implementation Plan

**Goal:** 批量按需解析并串行下载、串行上传，两个阶段可交叠；明确详情页 URL 优先。

**Architecture:** 使用一个下载生产者和一个上传消费者，按输入顺序交接准备好的任务。两份媒体容量限制确保最多一个上传中、一个下载中或待上传，链接只在下载阶段获取。同一个视频内部仍并行处理电报和夸克，沿用失败保留、用户决定重试/删除及双端成功清理。

**Tech Stack:** Python asyncio、现有 httpx/官方夸克 CLI、unittest 离线回归。

## 1. 输入与地址

- 修改 `scripts/common.py`：增加带 ID、标签、可选详情页地址的请求对象，支持多 ID 列表、多行 ID/URL/标签、大小写及中英文冒号；整批先校验再执行。同批重复 ID 合并标签和非冲突 URL，保持首次顺序。
- 保持旧 `parse_input` 二元组接口兼容；主入口使用新的完整请求解析器。
- 修改 `scripts/source.py`、`scripts/probe_video.py`：可选 URL 原样进入详情页请求；只接受 JAVHD 的无凭据 HTTP(S) URL，保留路径和查询参数，失败不回退拼接地址。沿用页面内部 videoId 和完整源解析。
- 修改 `scripts/task_files.py`：保存用户指定详情页 URL，旧任务缺省为空；不保存临时下载链接。

## 2. 两阶段调度

- 修改 `scripts/main.py`：`--id/--ids` 接收多个 ID，单任务增加 `--url`；复杂批量使用多行 `--input` 将 URL 绑定到各自 ID。
- 给单任务生命周期增加已准备媒体/准备失败的交接对象；首次批量上传不作为续传重试，已有任务重试仍从清单恢复。
- 下载生产者完整准备一个视频后交给上传消费者；只有一个生产者和一个消费者，上传消费者等双端结束后才处理下一条。媒体容量为二，任务在轮到下载时才创建和解析。
- 单条准备/上传失败均收尾保留并继续批次，批次最后汇总每项结果；运行锁覆盖整批。
- 中止时停止后续解析，等待已启动上传线程完成，保留已准备而尚未上传的任务，不自动删除或重传。

## 3. 验证及交付

- 新建 `tests/test_batch.py`：通过事件同步证明下载不重叠、上传不重叠、下一条解析时机、阶段交叠、双端并行、提前准备上限、失败继续、取消保留、逐项清理和批次锁。
- 新建 `tests/test_detail_url.py`：检查原样地址及内部 ID、无默认请求、无回退、任务及重试 URL、输入映射和无效输入的整批拒绝。
- 同步 README、SKILL 和运行协议，更新 ZIP 白名单；运行完整离线回归后重新打包，核对源文件、隐私排除、个人配置及 vendor 校验值。
